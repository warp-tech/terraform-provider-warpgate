# warpgate_secret_backend (Resource)

Manages a Vault or OpenBao server that Warpgate can use to resolve `secret://` references in target credentials and to sign SSH certificates for targets that use `certificate_auth`. Requires Warpgate 0.30 or later.

Warpgate never returns the token or AppRole secret ID it stores. The provider keeps the configured value in state, so a secret changed outside Terraform is not detected, and an imported backend shows the secret as a change until the next apply writes it.

`allowed_paths` limits what the backend may be used for. Each entry is matched on whole path segments: `mount/path` for KV reads and `mount/sign/role` for SSH certificate signing. Leaving it empty allows every path, so list exactly what Warpgate needs.

## Example Usage

```hcl
# Signs SSH certificates for targets that log in as "deploy", and nothing else.
resource "warpgate_secret_backend" "openbao" {
  name          = "openbao"
  backend_type  = "openbao"
  address       = "https://bao.example.com:8200"
  allowed_paths = ["ssh-warpgate/sign/deploy"]

  approle_auth {
    role_id   = var.warpgate_role_id
    secret_id = var.warpgate_secret_id
  }
}

# Warpgate running in Kubernetes, logging in with its service account.
resource "warpgate_secret_backend" "vault" {
  name          = "vault"
  backend_type  = "vault"
  address       = "https://vault.example.com:8200"
  namespace     = "infra"
  allowed_paths = ["secret/warpgate"]

  kubernetes_auth {
    role = "warpgate"
  }
}
```

## Argument Reference

The following arguments are supported:

* `name` - (Required) Name of the backend: letters, digits, `.`, `_` and `-`, up to 64 characters. Secret references and `certificate_auth` blocks refer to the backend by this name.
* `backend_type` - (Required) `vault` or `openbao`.
* `address` - (Required) Address of the server, e.g. `https://bao.example.com:8200`. Warpgate warns when it is not `https`, since the token would travel in clear.
* `namespace` - (Optional) Vault Enterprise or OpenBao namespace.
* `tls_skip_verify` - (Optional) Skip verification of the server's TLS certificate. Default: `false`.
* `allowed_paths` - (Optional) Path prefixes the backend may be used for. Empty allows every path.
* `token_auth` - (Optional) Authenticate with a static token. Exactly one of `token_auth`, `approle_auth` and `kubernetes_auth` is required.
  * `token` - (Required, Sensitive) The token. A renewable token is renewed by Warpgate before it expires.
* `approle_auth` - (Optional) Authenticate with AppRole. Warpgate logs in again when its token can no longer be renewed.
  * `role_id` - (Required) The AppRole role ID.
  * `secret_id` - (Required, Sensitive) The AppRole secret ID.
  * `mount` - (Optional) Mount path of the AppRole auth method. Warpgate uses `approle` when unset.
* `kubernetes_auth` - (Optional) Authenticate with the service account token mounted in the pod Warpgate runs in.
  * `role` - (Required) The Kubernetes auth role.
  * `mount` - (Optional) Mount path of the Kubernetes auth method. Warpgate uses `kubernetes` when unset.

## Attribute Reference

In addition to all arguments above, the following attributes are exported:

* `id` - The ID of the secret backend.

## Import

### Declarative Import Block (Terraform 1.5+ / OpenTofu 1.6+)

```hcl
import {
  to = warpgate_secret_backend.openbao
  id = "12345678-1234-1234-1234-123456789012"
}
```

### CLI Command (Terraform / OpenTofu)

```shell
# Using Terraform CLI
terraform import warpgate_secret_backend.openbao 12345678-1234-1234-1234-123456789012

# Using OpenTofu CLI
tofu import warpgate_secret_backend.openbao 12345678-1234-1234-1234-123456789012
```
